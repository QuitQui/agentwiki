Summary

This session implemented Phase 3 (hybrid search: Pagefind keyword + TF-IDF/LanceDB vector similarity) and Phase 4 (Kuzu knowledge graph) for AgentWiki. It also addressed Sourcery AI code review feedback on the Phase 3 PR, added a pytest suite covering both phases, and created this report.

The compiler pipeline now ends with two additional steps: build_search_index() computes TF-IDF cosine similarity and writes dist/similar.json + dist/lance/; build_graph() builds a Kuzu embedded DB and exports dist/neighbors.json and dist/graph_stats.json. The site exposes both through new UI sections and a dedicated /graph page.

Key Decisions

TF-IDF kept sparse until LanceDB write. Sourcery flagged that .toarray() before cosine_similarity() forces a dense O(n²·d) matrix. Fixed by passing the sparse matrix to cosine_similarity() and only densifying row-by-row when writing vectors to LanceDB.
Centralized dist/ path via AGENTWIKI_DIST_DIR env var. The Phase 3 PR hard-coded the path to dist/ in the Astro page, diverging from the compiler's --output-dir flag. Resolved by extracting similar.ts and graph.ts helper modules that read AGENTWIKI_DIST_DIR (falling back to the repo-root dist/) and cache the JSON at module level — matching the pattern already established in site/src/lib/data.ts.
Two separate Cypher queries for 1-hop / 2-hop neighbors. Kuzu's variable-length path syntax (*1..2) doesn't support min(length(e)) aggregation directly. Using two discrete MATCH queries and merging in Python is simpler and more explicit.
Canvas force graph with no npm dependencies. The /graph page uses a plain JS force simulation on a <canvas> element passed data via Astro's define:vars. This avoids adding D3 or other visualization libraries to the bundle.
