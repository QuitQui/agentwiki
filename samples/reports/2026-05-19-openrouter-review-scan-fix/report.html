Summary

This session had two goals: (1) close out the OpenRouter API migration in StrudelAI through a two-stage subagent review, and (2) diagnose and fix a long-standing AgentWiki limitation where reports from sibling projects were invisible to the compiler.

Decision — OpenRouter quality gate The spec compliance review passed cleanly. The code quality review identified four Important-severity issues in the streaming layer and model-persistence code. All four were fixed before the task was marked complete, matching the subagent-driven-development discipline of no open issues at merge time.

The four quality fixes in StrudelAI: a null-body guard before calling res.body.getReader() (crashes on network error without it), a try/catch wrapping JSON.parse(argsBuffer) (malformed model output would throw uncaught), loadModel() now validates the stored value against the FREE_MODELS whitelist (stale localStorage from a previous API would silently select an invalid model), and four unit tests for loadModel/saveModel added in models.test.ts.

Decision — Branch & PR rule added to CLAUDE.md The session that implemented OpenRouter committed directly to main. To prevent recurrence, a "Branch and PR workflow" rule was added to the workspace CLAUDE.md requiring all feature/fix work to go on a named branch and ship via gh pr create.

The AgentWiki discovery bug: compile_inputs() hard-coded a single lookup at input_dir/reports/. Reports from sibling projects like strudel-ai/reports/ were never visited. The fix adds a --scan flag that walks each given directory at depth-0 and depth-1, collecting every reports/ subfolder it finds, deduplicating by resolved path. Running uv run agentwiki compile --scan /path/to/workspace now surfaces 9 nodes where 5 were visible before.
