Summary

This session completed the final three sprints of the AgentWiki roadmap, delivering the full Phase 6 Agent API and upgrading the graph visualization layer. The goal was to make AgentWiki usable as a first-class knowledge source for AI agents — both via a REST API for programmatic access and via MCP for direct integration with Claude Code and Claude Desktop.

Sprint 3 introduced a FastAPI REST layer (compiler/api.py) with five endpoints: GET /nodes, GET /nodes/{id}, GET /search, GET /neighbors/{id}, and GET /stats. The API reads from the compiled dist/ directory and is wired into the CLI via uv run agentwiki serve.

Sprint 4 added an MCP server (compiler/mcp_server.py) exposing the same five capabilities as MCP tools over stdio. This allows Claude Code and Claude Desktop to call list_nodes, get_node, search_nodes, get_neighbors, and get_stats directly from the compiled knowledge graph.

Sprint 5 replaced the hand-rolled canvas-based force layout on the graph page with Cytoscape.js, loaded via CDN. A GlobalGraph.astro component handles the full knowledge graph view (cose layout), and a new LocalGraph.astro component renders per-node neighborhood graphs (concentric layout) directly on node detail pages. The Astro build produces 178 pages cleanly.

All phases of the AgentWiki roadmap (Phases 0–6) are now implemented. The project delivers a full compile → search → graph → API → MCP pipeline for AI agent project memory.

Open Questions

  • The MCP server has not been end-to-end tested with a live Claude Desktop or Claude Code session — only unit tested. A manual smoke test against the compiled dist/ would confirm the stdio transport works correctly in practice.
  • The REST API's /search endpoint uses naive case-insensitive substring matching on title/type. Future improvement: wire it to the existing Pagefind or LanceDB index for richer relevance ranking.
  • Node ID encoding (: → __, / → -) is duplicated between Python (_id_to_filename) and TypeScript (idToSlug) — could be consolidated into a shared utility or documented contract.
  • Phase 5 (tree-sitter codebase integration) remains marked as incomplete in CLAUDE.md, though getCodeSymbols() is referenced in the node detail page — the full tree-sitter extraction pipeline was not implemented in this session.
